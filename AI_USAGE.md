## 3. Which parts are AI-assisted

The **entire initial implementation was generated by Claude**: the scrapers (`scrapers/`), the cleaning, validation, deduplication and output code (`processing/`), `main.py`, `config.py`, all tests in `tests/`, the `Dockerfile` and the documentation.

Design decisions in the generated code that I reviewed and agree with:

- Requests + BeautifulSoup instead of Selenium (both sites are static HTML).
- One shared `BaseScraper` for networking and pagination; each site only defines selectors and `parse_item`.
- Scrapers return raw text; all cleaning is in separate pure functions, so cleaning is testable without internet.
- Validation returns a list of reasons, not True/False, so the summary can count rejections per reason.
- Duplicates are removed from the final CSV but kept in `duplicates.csv` for auditing.

## 4. Problems found in AI/reference suggestions, and what was changed

Rows 1-7 were found while building and testing the solution, and each is backed by a test that fails if the problem comes back. Rows 8-9 were found by running the scraper against the live sites.

| # | Suggestion (reference document snippets) | Problem | Change made | Proven by |
| --- | --- | --- | --- | --- |
| 1 | `Retry(backoff_factor=1.0)` "retries with 1s, 2s, 4s" | Wrong for urllib3 2.x: the first retry is immediate, so the waits are **0s, 2s, 4s** (checked with `Retry.get_backoff_time()`) | Documented the real timing in `config.py` and the README | Manual check of `get_backoff_time()` |
| 2 | Validate rating with `rating not in (1, 2, 3, 4, 5)` | `True in (1,2,3,4,5)` and `5.0 in (1,2,3,4,5)` are both `True` in Python, so a boolean or float rating would pass | Check `isinstance(rating, int)`, exclude `bool`, then range 1-5 | `test_validation.py` (`rating=True`, `rating=4.5`) |
| 3 | `clean_price` regex `\d+(?:\.\d+)?` | Ignores a minus sign, so `"-5.00"` becomes `5.0` and a bad price **passes** validation | Regex keeps the sign; validation then rejects it as `invalid_price` | `test_cleaning.py` (`-5.00`), `test_pipeline.py::test_bad_book_price_is_rejected` |
| 4 | Quote fingerprint takes `name_or_title[:50]` **before** normalizing | Leading spaces or quote marks shift the 50-character window, so the same quote can get different fingerprints | Normalize first, then take 50 characters | `test_deduplication.py::test_quotes_match_on_author_and_first_50_chars` |
| 5 | Fingerprint key built as one string `"source author text"` | Field boundaries are lost: `("a b", "c")` and `("a", "b c")` produce the same key | Normalize each field separately and join with `|` | `test_deduplication.py` |
| 6 | Default `Retry` settings | After the last retry urllib3 raises a generic `RetryError`, hiding the actual HTTP status | `raise_on_status=False`, then `raise_for_status()` reports e.g. "503 Server Error" | `test_http.py::test_permanent_error_gives_up_without_raising` |
| 7 | Rely on urllib3's own logging for retries | urllib3 logs status-code retries only at DEBUG level, so retries never appeared in `scraper.log` (found in a smoke test against a local server) | Added `LoggingRetry`, which logs every retry as a WARNING | `test_http.py::test_temporary_503_is_retried_then_succeeds` |
| 8 | Reference document: "your real run will probably find **0 duplicates**" (repeated in the first README draft) | The live run found **1**: Books to Scrape has two product pages titled *The Star-Touched Queen* | README now reports the real result and explains why the second listing is removed and kept in `duplicates.csv` | `output/duplicates.csv`, `logs/scraper.log` |
| 9 | Claude's estimate that a full run takes ~10-15 minutes | Real run took 1,368 s (~23 min): detail pages averaged ~1.3 s each (0.5 s delay + network round trip), not ~0.5 s | Updated the run-time figures in the README | `summary_report.json` (`duration_seconds`) |

The reference document itself was also incomplete: it was pasted twice and the first copy of snippet 5.7 (summary report) is empty.
